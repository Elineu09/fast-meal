1. Contexto: Estamos a iniciar o desenvolvimento do "Sistema de Atendimento de Fila do Refeitório". A arquitetura exige uma base de dados relacional que suporte utilizadores (estudantes, funcionários e admins), senhas (normais e prioritárias) e o histórico de atendimentos.
2. Tarefa: Criar o script SQL de criação da base de dados e a inserção de dados iniciais (seeds).
3. Requisitos: - Criar a BD e três tabelas obrigatórias: users (com roles), tickets (com status e type) e attendances (com timestamps).

Usar Chaves Estrangeiras (Foreign Keys) para relacionar tickets com users, e atendimentos com tickets.

Criar seeds com 1 Admin, 2 Estudantes e 2 Funcionários (passwords em hash estático para teste).
4. Formato de saída: Código SQL limpo, dividido em secções comentadas.
5. Restrições: Utilizar sintaxe compatível com MySQL/MariaDB. Nenhuma tabela extra além das solicitadas.
6. Saída esperada: Dois blocos de código: schema.sql (estrutura) e seed.sql (dados).

1. Contexto: O frontend em Angular precisa de se comunicar com o nosso backend para autenticar utilizadores.
2. Tarefa: Desenvolver a camada de acesso a dados (PDO) e os endpoints de autenticação em PHP puro.
3. Requisitos: - Criar config/database.php usando PDO com prepared statements e tratamento de erros (Exception).

Criar AuthController.php e AuthService.php com métodos para Registo e Login.

Utilizar password_hash() e password_verify().
4. Formato de saída: Ficheiros PHP completos com a estrutura de pastas indicada em comentários.
5. Restrições: Não usar frameworks, não usar ORM. Todo o retorno deve ser estritamente em JSON. Definir cabeçalhos CORS básicos.
6. Saída esperada: Código para database.php, AuthService.php, AuthController.php e a rota login.php/register.php.

1. Contexto: O sistema precisa gerir a emissão de senhas e a chamada pelo administrador, implementando a nossa "Funcionalidade Inteligente".
2. Tarefa: Desenvolver os endpoints de gestão de senhas (tickets) e o algoritmo inteligente.
3. Requisitos: - Lógica de geração: Estudantes recebem prefixo 'A', Funcionários recebem 'P' (prioritário).

Impedir que um utilizador tire uma 2ª senha se já tiver uma 'pendente'.

Criar um método inteligente no QueueService.php que calcule o tempo médio dos últimos 10 atendimentos para estimar o tempo de espera do utilizador atual.
4. Formato de saída: Código PHP estruturado por ficheiros.
5. Restrições: Seguir o padrão Controller -> Service -> Repository. O backend não gera o QR Code, apenas devolve os dados em JSON.
6. Saída esperada: Código para TicketController.php, QueueService.php, e rotas de pedir senha e listar fila.
